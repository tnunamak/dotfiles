## CLAIMS

- A PPTX generated by python-pptx can fail Google Slides import with "File could not
  open. Try refreshing the page" and an internal `AssertionException: expected a
  non-null reference` thrown at
  `TransformImporter.qdomOffsetToPunch` -> `transform2DToPunch` ->
  `shapeTransform2DToPunch` -> `ShapeImporter.toPunchShape`. [google-import-error]
- The trigger is coordinate attributes written with a decimal suffix inside
  `<a:xfrm>`, for example `<a:off x="2114550" y="3190875.0"/>` and
  `<a:ext cx="571500" cy="0.0"/>`. Google's importer expects integer EMU values and
  returns null when parsing the decimal form. [pptx-source]
- The failure is per-slide and silent about location: the error names no slide. Only
  the slides containing the malformed shapes fail, so bisecting slide ranges into
  separate files and importing each isolates them quickly. [pptx-source]
- Zero-valued extents (`cy="0"`) on perfectly horizontal or vertical connectors are
  NOT themselves the cause; patching zeros to 1 EMU leaves the import still failing
  while the decimals remain. [pptx-source]
- The fix is a regex pass over `ppt/slides/slideN.xml` stripping `.0` from x, y, cx,
  and cy, then rezipping:
  `perl -i -pe 's/(\b(?:x|y|cx|cy)=")(\d+)\.0"/$1$2"/g' ppt/slides/slide*.xml`
  followed by `zip -q -r -X out.pptx '[Content_Types].xml' _rels docProps ppt`.
  [pptx-source]
- Google's own conversion endpoint is a separate failure surface: `gog drive upload
  --convert` returned HTTP 500 internalError for every file tried, including files
  Drive accepted as a raw upload, so a 500 there is not evidence about the file.
  [gog-cli]
- The reliable oracle for "does this PPTX import" is opening the uploaded file's
  Slides URL in a browser and checking for rendered slides versus the error page.
  API-level upload success says nothing about import success. [gog-cli]

## SYNTHESIS

Two lessons generalize beyond this deck.

First, when generating OOXML programmatically for Google's importers, coerce every
coordinate to an integer before writing. python-pptx accepts float EMU values and
serializes them verbatim, which round-trips fine through LibreOffice and PowerPoint
and fails only at Google. Any pipeline that builds PPTX for Slides should add an
integer-coercion pass, or validate with a regex for `(x|y|cx|cy)="\d+\.` before
upload.

Second, the debugging method mattered more than the specific bug. Google's import
error names no slide and no shape, so the fast path is mechanical: split the deck
into single-slide files, import each, and bisect. That took one cheap agent about
five minutes after two rounds of hypothesis-driven guessing had failed. Prefer
bisection with a real oracle over reasoning about which shape "looks suspicious."

Practical note for agent-driven Slides work: `gog` covers presentation create, copy,
add-slide (full-bleed image), read-slide, update-notes, replace-slide, and
delete-slide, but has no command to edit text inside an existing shape. Text-level
editing requires calling `presentations.batchUpdate` directly.
