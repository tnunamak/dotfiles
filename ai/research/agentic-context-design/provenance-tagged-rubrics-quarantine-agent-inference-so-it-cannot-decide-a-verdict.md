## CLAIMS

- In one documented case (a site-design judging rubric, four completed rounds, all scored PASS), a rebuild of the rubric found that the test which had actually decided every verdict — a "noun-swap counterfactual" (rebuild the candidate with the subject's nouns swapped for a different protocol's, and check whether its claims become false) — appeared zero times in the owner's own 150-turn verbatim transcript. The owner never asked for it, never described it, never approved it; it was invented downstream by the agents building the rubric and then treated as though it were the owner's own litmus test. [gate-v2-case-study]
- In the same case, an earlier document had correctly tagged a rule ("do not average across N good reference sites") as `[AGENT INFERENCE]` — an explicit admission it was the agent's own idea, not something the owner said. A later rubric document built a mandatory PASS/FAIL gate directly from that rule without carrying the tag forward; the caveat that would have kept it advisory was dropped in the handoff between documents. The same pattern recurred with a second rule (a "register" standard) that had been tagged `[FROM <source>. NOT the owner.]` and was later promoted to a hard gate with the tag gone. [gate-v2-case-study]
- In the same case, the rubric's primary reference set (the sites used to judge whether a design choice was "derived" rather than arbitrary) covered only one derivation class — "the subject's identity determines its visual grammar" — because both worked examples in the rubric happened to share that shape. The rubric therefore never tested the one property that mattered most for the actual subject (how a neutral standard names a dominant, named external implementer without becoming that implementer's marketing page), because no reference in the set required it. Four rounds of judging produced PASS verdicts against a reference set that structurally could not surface the hardest real question. [gate-v2-case-study]
- In the same case, every gate in the superseded rubric was either mechanical (regex/grep-style) or markup-level (does this HTML pattern exist); none required a human or agent to actually place the candidate beside a reference image and look at it. The owner found the real defect in seconds by doing exactly that, unprompted, directly comparing screenshots. A rubric with four rounds of passing verdicts had zero visual side-by-side gates and missed what a five-second look caught. [gate-v2-case-study]
- The rebuilt rubric's fix was structural, not just corrective: every gate carries a mandatory PROVENANCE tag from a closed set — `[OWNER QUOTE]` (a direct quote, citable by timestamp — the only category that can independently fail a candidate), `[OWNER-ENDORSED EVIDENCE]` (something the owner directly looked at and reacted to, with the reaction cited, weighted by how unambiguous the reaction was), or `[AGENT INFERENCE]` (reasonable derived guidance with no owner statement or reaction behind it). [gate-v2-case-study]
- The rebuilt rubric states the rule as a structural constraint on the rubric itself, not a style preference: "An AGENT INFERENCE gate is always advisory. It may be reported, and it may inform a note to the next iteration, but it can never by itself produce a FAIL verdict on the candidate, and it is never counted toward the PASS bar." A gate with no provenance tag is defined as malformed and barred from use; a gate tagged AGENT INFERENCE but written as though it could fail the candidate is named as the exact defect the rubric exists to prevent. [gate-v2-case-study]
- The rebuild required an explicit, separately-stated discard list at the top of every judged report — which prior tests/gates/PRESERVE-items were being formally withdrawn and why — specifically so a reader encountering only the new rubric would not re-litigate a withdrawn finding as though it were still live, and so a prior PASS verdict scored under the superseded rubric could not be cited as precedent going forward. [gate-v2-case-study]
- The rebuild replaced a numeric/aggregate score with an unweighted all-gates-must-pass bar, on the explicit reasoning that a numeric score reintroduces the averaging failure the rubric exists to prevent: a candidate could look "good in aggregate" against a scored total while still failing one gate that traces to something the owner said directly — treating that failure as equivalent in weight to unrelated passing gates is a category error. [gate-v2-case-study]
- The rebuild added a specific new gate class (naming: does the site's treatment of a named external implementer trace to a stated, procedural admission criterion, or is it an editorial choice that currently reads as neutral but has no structural reason it couldn't drift) directly because breadth research the owner had separately asked for surfaced reference sites (a W3C identifier spec, an identity-federation standard, a federated-chat protocol) where exactly this property was the actual differentiator between clean and leaking cases — evidence that narrow reference sets don't just bias results, they can make an entire class of real failure invisible to every gate in the rubric. [gate-v2-case-study]

## SYNTHESIS

The mechanism generalizes beyond this one case, and it is worth naming plainly: any rubric built iteratively by agents, across multiple documents, will silently launder inference into requirement unless the provenance of every rule is tracked as a first-class, mandatory field and re-checked at every handoff. The failure isn't sloppiness in any one document — the "do not average across references" rule was honestly tagged as an inference when it was written. The failure is structural: nothing forced the next document that built on top of it to preserve that tag, and a rule stated as a hard requirement reads identically to a rule stated as an inference once the caveat is gone. Tagging has to be enforced at the point of use (every gate carries its own tag, checked every time), not just at the point of origin.

The two other failures in this case are worth separating from the provenance problem because they call for different fixes. The narrow-reference-set failure (only one derivation class tested, so an entire class of real problem was invisible to every gate) is a coverage problem — the fix is deliberately seeking out a reference case that has the structural property under test, not just more references of the same shape. The no-one-looked-at-it failure (zero visual gates in four rounds of judging a visual artifact) is a completeness problem — a rubric composed entirely of gates that are individually well-specified can still, in aggregate, never require the one check that would have caught the actual defect, if that check's *modality* (looking at an image, not parsing text) was never represented in the gate set at all.

Relation to existing corpus material: `agentic-context-design/llm-judge-and-checklist-rubric-evaluation-literature-for-loop-engineering.md` covers the academic literature on LLM-as-judge reliability (JudgeBench, RubricEval, CRITIC) and converges on a related but distinct lesson — ground critique in external tools/evidence, don't trust introspection, and no single judge is reliable across all settings. This entry's finding is complementary and more specific: even when a judge (human or agent) *is* grounded in real evidence, a multi-document rubric-authoring pipeline can still silently convert "the agent's best guess" into "an unambiguous requirement" through nothing more than a dropped tag across a document boundary — a maker-not-judge failure that happens in the rubric's own authorship chain, not in the judging pass itself. The provenance-tag discipline is a directly reusable pattern for any agent-authored evaluation rubric, independent of whether the artifact being judged is a website, a codebase, or prose.
