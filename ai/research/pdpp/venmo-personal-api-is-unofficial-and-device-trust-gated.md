## CLAIMS

- [venmo-login-security] Venmo says a sign-in from a new browser or a browser with cleared cookies can be treated as a new device and can require two-factor verification.
- [venmo-login-security] Venmo documents two-factor verification as part of sign-in security and describes verification for a new device.
- [paypal-pay-with-venmo] PayPal's official Venmo integration documentation describes merchant checkout, including a PayPal business account, client ID, and supported checkout flow.
- [venmo-oss-403] The `mmohades/Venmo` issue tracker contains a report of the same OAuth2 access-token failure text with HTTP 403.
- [py-venmo-device-id] The active `joshhubert-dsp/py-venmo` README describes its API as unofficial, reports device-trust and cooldown behavior, and says random device identifiers are rejected in favor of a real device identifier in its experience.

## SYNTHESIS

The old password-grant plus synthetic-device-ID path should not be revived by changing headers, retrying, or inventing a client identifier. The official material found documents Venmo sign-in verification and merchant checkout, while credible unofficial clients report the same 403 family and device-trust sensitivity. The current connector's browser-session path is the only candidate that can honestly accommodate owner verification, but it must remain unlisted and unproven until a bounded owner-assisted, read-only run proves all declared streams and session reuse.
