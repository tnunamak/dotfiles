## CLAIMS

- Claude Code's Agent View models six *display* states — Working, Needs input, Idle, Completed, Failed, Stopped — plus three orthogonal process-liveness glyphs (`✻`/`✽` alive, `∙` process exited but resumable, `✢` `/loop` sleeping). [claude-agent-view]
- Claude Code's Agent View `--json` output emits a *different, smaller* machine state set: "one of working, blocked, done, failed, or stopped" — i.e. the human display taxonomy and the machine taxonomy are deliberately not identical. [claude-agent-view]
- Claude Code's Agent View orders the list by GROUP, not by recency, in this fixed top-to-bottom order: Pinned → Ready for review → Needs input → Working → Completed. [claude-agent-view]
- In Claude Code's Agent View, a session enters the "Ready for review" group specifically when it has an open pull request; the "Completed" group collects finished, failed, and stopped sessions together. [claude-agent-view]
- Claude Code's Agent View shows a one-line per-row summary generated by a Haiku-class model that states, depending on state, what the session is doing, the question it is asking, or its result. [claude-agent-view]
- Claude Code's Agent View fires two notification types through the configured terminal channel: `agent_needs_input` (a background session starts needing input) and `agent_completed` (a session finishes or fails). [claude-agent-view]
- Devin's session status uses two layers: a machine `status_enum` (working, blocked, expired, finished, plus suspend/resume request variants) and UI action-oriented labels such as "PR created", "Awaiting instructions", and "Approve session" shown alongside timestamps; GitLab review is grouped into buckets "Needs your review, Returned to you, Approved, Waiting for reviewers, Drafts". [devin-sessions]
- Devin lets sessions be pinned to the top of the sidebar and otherwise sorts by creation date, and marks sessions with unread updates using an orange dot. [devin-sessions]
- Vibe Kanban ran two parallel state models: an issue-level board (To do / In progress / In review / Done, plus hidden Backlog / Cancelled) and a session-level "Workspaces" model with states Running, Idle (waiting for your input), and Needs Attention (waiting for approval or has a question), with the sidebar grouped by Running / Idle / Needs Attention. [vibe-kanban]
- Crystal modeled six color-dotted states — Initializing, Running, Waiting (needs your input), Completed, New Activity (session has new unviewed results), Error — where "New Activity" (unviewed output = needs-review) is a state distinct from "Waiting" (needs-input). [crystal]
- claude-squad models only four states (Running, Ready, Loading, Paused) and its "Ready" state conflates "done, review me" with "blocked, waiting for user input" because it is detected by diffing tmux pane content on a 500ms tick (screen-scraping), not from agent hooks. [claude-squad]
- claude-squad orders its session list by insertion order only, with no sort, and ships no notifications (no sound, desktop, or push). [claude-squad]
- Conductor organizes workspaces by a kanban lifecycle (backlog, in progress, in review, done), surfaces "needs permission" and unread/attention conditions separately from that lifecycle, and moves a shared workspace up the sidebar when a collaborator sends a prompt. [conductor]
- tmux-agent-status's "agents" view sorts panes by the priority order `ask, done, working, wait, parked`, placing the items needing user input first. [tmux-agent-status]

## SYNTHESIS

The single most consistent finding across the 2025-2026 wave is a **two-axis state model**, and the quality of a product's supervision UX tracks almost perfectly with whether it separates the two axes:

- **Axis A — lifecycle** (what the agent is doing): working/running → idle → done/completed → error/failed → stopped/paused/expired.
- **Axis B — supervisor action required** (the supervision-critical axis): needs-input (agent asked you a question / permission), needs-approval, needs-review (finished, produced output/PR you haven't looked at).

The best consoles (Claude Agent View, Devin, Vibe Kanban Workspaces, Crystal) split Axis B out and rank it above Axis A. The weak one (claude-squad) collapses "done, review me" and "blocked, asking you" into one "Ready" state precisely *because* it screen-scrapes pane content instead of reading agent hooks — it structurally cannot tell the difference, so it can't rank on Axis B. This is a direct argument for our own design: **hook-derived state is what makes the needs-you distinction possible; screen-scraping caps you at a conflated state model.**

Two orderings are worth stealing near-verbatim as our default:
- Claude Agent View: `Pinned → Ready for review → Needs input → Working → Completed`.
- tmux-agent-status: `ask → done → working → wait → parked`.

Both put "needs you" at the top and demote "working" to the middle — the opposite of a recency-sorted list. Recency is the default in the *cloud-task-queue* products (Codex, Cursor "newest first") but those are task-submission surfaces, not many-worker supervision surfaces; for supervision, group-by-state + needs-you-first is the convergent answer.

The **PR-keyed "Ready for review"** signal is the highest-value single idea: Claude, Devin, Conductor, and Vibe Kanban all elevate "has an open PR / in review" to a top-ranked state. For our fleet that maps to: a window whose agent has opened a PR (or otherwise produced a reviewable artifact) is the thing the supervisor should see first.

The **one-line Haiku-generated per-row summary** in Claude Agent View is the standout at-a-glance move — it answers "what is this window doing / what does it need / what did it produce" without attaching. Any bespoke build should treat a short state-appropriate summary line as a first-class field, not decoration.

Caveats on volatility: Crystal is deprecated (Feb 2026), Vibe Kanban is sunsetting, and Conductor's exact notification transport is unconfirmed. The *patterns* they established (two-axis state, needs-review split, board grouping) outlived the specific products, which is why they belong in the corpus even though two of the tools are dead.
